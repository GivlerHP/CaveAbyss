# Negative chunk synchronization and DH support

Versions: CaveAbyss 1.0.2.50 and AriamisDistantHorizons 1.1.6.

Client snapshots, light snapshots and deltas wait for an actual loaded Chunk,
rather than applying to ChunkProviderClient's shared EmptyChunk. The deferred
queue preserves packet order per chunk and discards state on chunk/world unload.
Layer creation is atomic across renderer workers and the packet application thread.
Snapshot render invalidation includes adjacent blocks/sections/chunks, so faces
built while neighboring negative data was absent are rebuilt when it arrives.
Server deltas and tile packets target chunk watchers instead of a 128-block sphere.

The optional DH integration exposes the -64 minimum through level/chunk wrappers,
reads all 320 block levels and negative light emitters, and waits for all four
custom block snapshots before converting a client chunk. Snapshot completion,
block deltas and light updates notify DH after vanilla fillChunk's original event.
Its readiness tracker, quad masks, mask texture and fragment shader use 20 distinct
section bits/layers. GPU mesh lookup accounts for Neodymium's shifted array slots.
An empty dirty renderer does not hide LODs for newly arrived nonempty terrain.
Other dimensions retain their original minimum height.

Extended levels use DistantHorizons-minY-64.sqlite, preserving the original
DistantHorizons.sqlite without reinterpreting its relative heights.

Validation: both Gradle builds/checks pass; CaveAbyss's deferred delivery smoke
test covers delayed readiness, packet ordering, duplicate drains and unloading.
Existing production, OptiFine, Neodymium and vertex checks pass. The standalone
tools/dh-height-check fixtures exercise DH's production ChunkWrapper height API,
readiness tracker and optional API bridge. They also compile/link the production
terrain shaders in an offscreen LWJGL Pbuffer and verify pixel output for every
section Y=-64..255, missing meshes, and a negative-height top-face boundary.
The world and GPU-readiness inputs are fixtures; the full game/mod chain still
requires in-game validation.

Run tools/dh-height-check/run.py with --dh-root, --java-home, --lwjgl and --natives.
It uses DH's build/dh-checks/classpath.txt (generated by its existing
writeDhCheckClasspath init script).

1.0.2.51 / DH 1.1.7 follow-up:
RenderGlobal's markBlocksForUpdate now calls markDirty even when needsUpdate is
already true. Queue insertion remains conditional. This lets FalseTweaks cancel
a worker that read a lower section before a snapshot/delta arrived, instead of
committing an obsolete empty mesh. The inserted branch preserves stack frames.
RenderInvalidationSmoke executes the patched real vanilla method across all 20
sections and checks two invalidations but one queue entry per renderer. Production
Forge/SRG/OptiFine bytecode and Neodymium checks also pass.

DH no longer fills cave air segments into the previous roof LOD when the segment
extends into negative world heights. The original surface optimization and user
setting remain effective above zero. This avoids artificial vertical roof pillars
through the open CaveAbyss layer; it can retain more real cave geometry than the
old fill optimization. Existing full-data databases remain usable because the
change is in full-data-to-render conversion, not block storage. In-game visual
verification of the reported travel/rejoin scenario remains necessary.

DH 1.1.8 supersedes the height-specific cave-culling fix above: the reported
pillars occur above zero as well. Cave culling now skips hidden cave entries
without calling setYMin on the previous solid LOD. This removes artificial roof
extrusion at every height. The negative-height-only boundary is removed. The
other adjacency merge still requires a shared face, so it does not bridge air.
This preserves actual gaps and can increase visible cave geometry versus filling
them with solid columns. Full-data storage is unchanged; restart reconstructs
render data. In-game confirmation remains required.

DH 1.1.9: reproduced the remaining all-height interior strips in the production
readiness tracker. hasNeoGpuMesh incorrectly required mesh.visible,
WorldRenderer.isVisible and isInFrustum, so occlusion/frustum rejection resurrected
an LOD where native geometry was deliberately hidden. Readiness now depends on
initialized native geometry and a SENT GPU mesh, independently of visibility.
Vanilla display-list readiness likewise uses initialization, not a prior draw.
Removed the renderSortedRenderers observer and per-draw coordinate allocations.
The stability delay, unloaded/repositioned renderer handling and missing/UNSENT
GPU fallback remain. Extended DhHeightReadinessCheck first failed on 1.1.8 for
occluded GPU geometry, then passed at all 20 heights after the fix. It also checks
vanilla sections never drawn and UNSENT fallback. Production GL mask tests pass.
The screenshots still require visual verification in the full modded client;
this regression test reproduces the erroneous visibility/readiness decision.

DH 1.1.10: investigated actual mesh emission rather than readiness masking.
ColumnBox.makeAdjVerticalQuad accepted adjacentIsSameDetailLevel but ignored it.
The border seam fallback emitted a lit vertical quad even when an opaque neighbor
at the same detail level completely covered it. The fallback now applies only
at mixed-detail transitions. Geometry checks execute the production ColumnBox
and LodQuadBuilder: the old code emitted one covered face; the fix emits zero.
All four border directions, lit/unlit solid neighbors and relative heights
corresponding to Y=-64..255 are tested. Real exposed half-faces, open-air faces
and mixed-detail transition fallback are retained. These checks validate actual
quad counts and heights, independently of the readiness mask and OpenGL.
Run python tools/dh-geometry-check/run.py using the existing DH classpath file.
In-game verification is still needed to establish whether this accounts for all
of the remaining screenshot artifacts. No FPS improvement has been measured.
